## 1. 背景与目标

在 `c-lib/shell-command-link` 新建一个**可移植、低占用**的「shell + 指令链脚本」库（下称 SCL，Shell-Command-Link）：

- 输入：一段由 `;` 分隔的指令链（"脚本"），形如 `cmd...;var a=1;...`
- 支持：变量（`${var}` 取值）、函数式调用、`G_RETURN` 条件标志、`if` / `while` 控制流
- 输出：作为**可复用组件库**，无 HAL / OS / 业务依赖，仅通过移植接口对外输出
- 内存：全程静态内存、无 `malloc`；运行时内存占用设计目标 < ~300 B（含内部脚本缓冲则视配置而定）

### 从参考工程 `app_shell` 借鉴/继承的点
- 命名与工程习惯：严格中文注释、模块前缀 + 大写下划线宏、`Inc/Src` 目录、`extern "C"` 包裹
- 指令以 `;` 分隔的"指令链"心智模型（参考工程已实现 `;` 链 + `while -b/-e/-c` 记录运行）
- 双引号参数：`TokenizeLine` 已支持 `"..."` 视为整体并剥离引号 —— 本次需**升级为"分号分割时跳过双引号内内容"**，否则 `if -t "a;b"` 无法表达多指令分支
- 静态环形缓存思路可借鉴，但本次采用**同步整脚本解释执行**，不需要环形排队（见 §5.3）

## 2. 需求梳理

| # | 需求 | 关键词 |
|---|------|--------|
| R1 | `var name=value` 建变量；上限 2 个；值存 16 byte 字符串 | 变量 |
| R2 | 其它指令内 `${name}` 展开取值 | 展开 |
| R3 | C 命令处理函数可通过接口读变量 | 读接口 |
| R4 | 变量可 `free`；可查剩余空位；脚本跑完自动全 free | 释放 |
| R5 | 全局标志 `G_RETURN` 默认 false，读后重置 | 条件 |
| R6 | 普通调用 + 函数式调用 `cmd_xxx(a,b,...)` | 调用形式（注：函数式已在 v2 移除，见 §5.1） |
| R7 | `if -t x -f y` 按 G_RETURN 执行分支 | 条件执行 |
| R8 | `while -b; body; while -e` 按 G_RETURN 决定退出 | 循环 |
| R9 | 占用低；做成库；提供移植接口 | 约束 |

## 3. 左右脑互博

### 3.1 左脑（工程派 / 保守 / 可移植性 / 低占用）

左脑先列约束与疑虑：

- L1 **歧义是最大的成本**：`if -t xxxx` 里 `xxxx` 到哪结束？后面若还有 `;` 分隔的指令，属于 `-t` 分支还是 if 之后的下一条？不定义清楚，解析器和用户都会踩坑。
- L2 **执行模型必须同步简单**：这是 MCU 风格库，脚本很短。若做成"每条指令一个状态机 + 跨 Loop 恢复"，if/while 的跳转状态、变量生命周期、G_RETURN 读后重置都会非常复杂，占用也压不下来。
- L3 **解析要一次性、可预测**：`while -e` 要跳回 `while -b` 重跑 body，说明必须先把整段链**结构化**（定位 while 对），不能逐字符乱猜。while 必须**有最大迭代保护**，防止死循环把 MCU 卡死。
- L4 **内存预算严格**：2 个变量槽、无动态内存。若再加"内部脚本拷贝缓冲 + 每层分支缓冲 + argv 展开缓冲"，要逐个说清占用，能省则省。
- L5 **C 命令处理函数必须是快速、非阻塞的**：否则同步执行器被一条 `cmd_xxx()` 卡住，while/if 全部失去意义。参考工程里电机指令是异步的（靠 sync 回调），这套东西若想直接搬，需明确边界。
- L6 函数式调用 `cmd_xxx(a,b)` 与普通调用 `cmd_xxx a b` 并存会有二义性（如字符串里含 `,` / 参数含空格）——要定优先级与书写规则。
- L7 `G_RETURN` "读后重置" 要定死在**哪几个点算"读"**（if、while-e），避免条件值被意外吞掉或残留。

### 3.2 右脑（体验派 / 发散 / 好用）

右脑提更顺手的方案：

- R1 `if -t/-f` 分支应该允许**多指令**：`if -t "move(10);wait_done()" -f "alarm()"`，用双引号包一整段子链，直白表达"满足条件干一堆事"。
- R2 支持 **if/while 相互嵌套**（如 `while` 内 `if`、`if` 内再 `while`），脚本表现力才够；但嵌套深度用编译期宏封顶。
- R3 `${var}` 应支持**拼接**（`${a}deg`），不然只能整 token 替换，写命令时到处要引号。
- R4 提供**结果可视**：`var`（无参）列出现有变量与剩余槽位、`help` 列出命令、错误提示尽量带行/段上下文。
- R5 `G_RETURN` 语义做成"谁读谁清零"的**一次性令牌**，if/while/命令三方都不会拿到脏值。
- R6 while 最好还能带"上限次数"参数（`while -e N` 或自动保护），且支持**中途 Abort**（外部可强制打断正在跑的脚本）。
- R7 输出做成可裁剪：关闭消息后连移植打印函数都不必实现，适合"静默跑脚本"场景。

### 3.3 交锋逐条（左 vs 右 → 合议）

| 议题 | 左脑 | 右脑 | 合议（本次默认） |
|------|------|------|------------------|
| `if -t/-f` 分支边界 | 只允许单条指令，`;` 一律是链分隔，最无歧义 | 允许双引号包多指令子链 | 解析器"按引号保护分割 `;`"；`-t/-f` 后：双引号内=多指令子链；否则=到该 token 结束的单指令（默认）。由 §4 问题 2 确认 |
| 执行模型 | 整脚本同步一次跑完最简单 | 想异步/逐条步进 | **已确认：异步/跨主循环步进**：`SCL_Run()` 把脚本切词成"内部程序"后立即返回并置 busy；主循环周期调 `SCL_Loop()` 推进；命令可带"同步信号回调"（handler 启动异步操作后立即返回，库每 Loop 轮询 `sync(false)`，完成后再 `sync(true)` 清除并继续下一条）。由问题 3 确认 |
| 结构化 | 解析要结构化 & while 要有配对/上限 | 上限 + Abort 要能打断 | 内部程序**文本拷贝持久化**（跨 Loop tick，只读不改写）；执行用**显式帧栈 + 文本游标**逐子句推进；`while -b` 首次执行时扫描定位配对 `while -e` 存入帧；`while -e` 最大迭代 `SCL_CFG_WHILE_MAX`（默认 100000）防死循环；提供 `SCL_Abort()` |
| 分支/嵌套 | 尽量不嵌套、省内存 | 想嵌套 | 允许嵌套，深度宏 `SCL_CFG_MAX_NEST`（默认 3）封顶；执行用显式帧栈（非真递归） |
| ${} | 仅整 token 替换，最简单 | 想拼接 | 支持**拼接替换**，展开结果写入可配长度的工作缓冲，超长报错（默认展开后单 token ≤ 32 B，可裁） |
| 函数式/普通调用 | 必须无二义 | 想两者都留 | 语法：命令名后**紧邻 `(`** 即函数式（`cmd(a,b)`，逗号分隔、引号保护）；否则按空白分隔普通调用。`cmd` 后空格再 `(` 视为普通调用的参数 |
| G_RETURN | 定死读点 | 一次性令牌 | 全局 bool（封装，不裸奔）；`if`、`while -e`、任一"读接口"读取即清零；命令侧只能 `SCL_Ret_Set()` 写；每条链开始也清零一次（防历史残留） |
| 变量 | 2 槽写死也行 | 想可配 | 槽数/名字长/值长全部可配宏：默认 2 槽 / 名 ≤ 8 / 值缓冲 16 B（含 `\0`，即 15 字符）。由问题 4 确认默认值 |
| 内存 | 无 malloc，能省则省 | 想内置脚本拷贝 | 异步执行需跨 tick 保存程序，**统一走内部缓冲**（`SCL_CFG_SCRIPT_MAX`，默认 256 B），调用方传任何缓冲/字面量皆可（库自行拷贝）；不再提供 0 拷贝入口。由问题 3 确认 |

## 4. 关键歧义确认结果（用户已确认 2026-09-07）

1. `while -e` 退出极性：**`G_RETURN==false` → 退出循环**（类似 C `while(G_RETURN)`，循环条件是 G_RETURN 为真）。每次读到 G_RETURN 即清零。
2. `if -t/-f` 分支：**允许双引号包裹的多指令子链**（`if -t "a;b"`），且 **if/while 可嵌套**（深度宏默认 3）。
3. 执行模型：**异步/跨主循环步进**。命令可能耗时等待硬件（如电机），库支持每条指令分步执行 + 命令级同步信号回调（详见 §5.3）。复杂度高，占用预算相应上调。
4. 变量默认尺寸：**2 槽 / 名 ≤ 8 / 值缓冲 16 B（15 字符）**，均可用宏改。
5. PC 侧示例/测试工程：**需要**，并跑全量测试：大小 / 速度 / 可靠性 / 重复性 / 复杂度；提供基础演示命令（可裁剪）。

## 5. 合议后的最终设计

### 5.1 语法定义（建议稿）

```
<脚本>      ::= <子句> { ';' <子句> }            // 引号内 ';' 不分割（引号保护）
<子句>      ::= 变量指令 | 流程指令 | 业务命令调用
<变量指令>  ::= 'var' <名> '=' <值>             // 名与值均不可含 ';' ' ' '='
              | 'var'                          // 列出变量与剩余槽位
              | 'var' 'free'                   // 全部释放（同 free）
              | 'free' [<名>]                  // 释放指定变量；无参=全释放
<流程指令>  ::= 'if' ['-t' <分支>] ['-f' <分支>] // 读 G_RETURN（读后清零）
              | 'while' '-b'                   // 循环开始（标记 body 起点）
              | 'while' '-e' [<上限>]          // 读 G_RETURN 决定退出；可选显式上限
<分支>      ::= '"' <脚本> '"'                 // 双引号：多指令子链
              | <命令文本>                     // 单 token：单条命令（不含 ';'/' ')
<命令文本>  ::= <命令名> { ' ' <实参> }               // 普通式：空白分隔（函数式调用已移除）
<实参>      ::= [ '"' ] <串含 ${var} 展开> [ '"' ]
```

要点：
- `${name}` 展开：作用于实参 token 解析阶段，支持拼接（`${a}deg`），展开结果受工作缓冲长度限制，超长报错。
- `G_RETURN`：`if`、`while -e` 读取即清零；C 命令用 `SCL_Ret_Set(bool)` 写入。
- `while -e` 语义（已确认）：读到 G_RETURN==false → 退出循环；==true → 回跳 `while -b` 后继续 body（do-while 风格，即 C `while(G_RETURN)`）。
- 业务命令名**不带** `cmd_` 前缀也可以注册（前缀只是惯例），注册即生效。
- **v2 变更（2026-09-07）**：命令调用只保留**普通式 `cmd a b`**；函数式 `cmd(a,b)` 已从实现中移除（输入会被当作"未知命令"报错）。modern 语法层（`tools/scl_script2chain.py`）仍用括号书写、转译时输出普通式。

### 5.2 示例脚本

```
// 电机测试风格（伪命令）：
var t=3
while -b
  step 100 ${t}          // 走 100 步，写 G_RETURN=是否到位
  if -t "log ok" -f "log retry;step -10"
while -e
var free                  // 脚本尾部显式释放（其实脚本结束也会自动全释放）
```

### 5.3 架构与执行模型（异步/跨主循环步进，已确认）

- **入口**：`SCL_Run(const char *script)`：把脚本**拷贝**进内部程序缓冲（`SCL_CFG_SCRIPT_MAX`）并做结构预检（引号平衡、`while -b/-e` 计数平衡、长度上限），通过后置 busy 立即返回；调用方缓冲可即刻复用。busy 时新 Run 拒绝并提示。
- **运行态状态（全部静态，跨 Loop tick 存活）**：内部程序文本（执行期间**只读不改写**）＋ 当前段游标 ＋ **显式执行帧栈**（上限 `SCL_CFG_MAX_NEST`）＋ 异步等待节点 ＋ G_RETURN/忙标志。
- **`SCL_Loop()` 每周期推进**：
  1. 若有业务命令处于异步等待 → 轮询其 `sync(false)`；未完成即返回；完成则 `sync(true)` 清除 → 继续下一步；
  2. 否则取下一条子句执行（普通/函数式命令、`if`、`while -b/-e`、`var`/`free`）→ 其中命令可能是新的异步等待点；
  3. 顶层段结束 → 弹空帧栈、**自动释放全部变量**、G_RETURN 清零、置空闲。
- **`while -b`**：首次执行时在当前段内扫描定位配对 `while -e`，压循环帧 {body 起点、-e 位置、迭代计数}。
- **`while -e`**：读并清零 G_RETURN：==false 或超迭代（`SCL_CFG_WHILE_MAX` 兜底，子句可带显式 `-e N` 上限）→ 弹帧退出；==true → 游标回跳 body 起点（do-while）。嵌套 while 帧在栈上自然配对。
- **`if`**：读并清零 G_RETURN；按真/假选中 `-t/-f` 分支；分支为双引号子链时压"段帧"（分支文本区间）作为内层执行段，结束弹帧回到 if 之后。
- **帧 = 段 / 循环两类**：段帧提供"内层文本区间"（if 分支子链、顶层）；循环帧提供"回跳点 + 终止点"。不 C 递归，全部由显式帧栈承载，故天然可挂起（跨 tick）。
- **`SCL_Abort()`** 置位后，在子句边界/异步轮询间隙检查，置位立即停并报 "aborted"（变量仍自动释放）。
- 已知取舍：**一次只跑一个脚本**（busy 即拒）；需要排队由应用层自行管理（参考工程有环形排队，可作后续扩展）。

### 5.4 内存/占用估算（默认配置）

| 项 | 大小 | 说明 |
|----|------|------|
| 变量表 | 2 × (8 名 + 16 值) ≈ 48 B | 槽/名/值长均可配 |
| 内部程序缓冲 | 256 B | 异步跨 tick 必需，`SCL_CFG_SCRIPT_MAX` |
| 执行帧栈 | 3 × ~24 B ≈ 72 B | `SCL_CFG_MAX_NEST=3` |
| 实参/展开缓冲 | 8 × 32 B = 256 B | `SCL_CFG_ARG_MAX × SCL_CFG_ARG_LEN_MAX` |
| 其它状态（游标/忙/异步节点/G_RETURN） | < 64 B | 静态 |
| **运行态静态合计** | **~0.7 KB** | 无 malloc；实际以 PC 测试 `size` 实测为准 |
| 代码段 | 目标 < 5 KB（可裁剪功能） | 关闭消息/帮助后更小 |

> 无 `malloc`、无 OS、无 HAL 依赖。

### 5.5 API 草案（前缀 `SCL_`）

```c
/* 生命周期 */
void     SCL_Init(void);                    // 清命令表/变量/G_RETURN（可选，首次运行自动）
uint8_t  SCL_Run(const char *script);       // 拷贝并开始执行一条链；返回 1=成功，0=忙/超长/结构错误
void     SCL_Loop(void);                    // 主循环周期调用：推进执行（含异步等待轮询）
uint8_t  SCL_Idle(void);                    // 返回 1=空闲（无脚本执行/无异步等待）
void     SCL_Abort(void);                   // 请求中断当前脚本（从其它上下文调用）

/* 命令注册（命令节点由所属模块静态定义，参考工程同款单向链表） */
typedef void (*scl_cmd_t)(int argc, char *argv[]);   /* 处理函数：立即发起并快速返回 */
typedef bool (*scl_sync_t)(bool clear);              /* 可选同步信号：false=查询是否完成；true=完成确认后清除 */
typedef struct scl_cmd
{
    const char    *name;   /* 命令名 */
    scl_cmd_t      fn;     /* 处理函数 */
    scl_sync_t     sync;   /* 同步信号（NULL=同步命令；非 NULL=异步需等待） */
    struct scl_cmd *next;  /* 链表下一节点（SCL_RegisterCmd 维护） */
} scl_cmd_t;
void     SCL_RegisterCmd(scl_cmd_t *cmd);   // 挂载命令节点到命令链表

/* 条件返回（命令处理函数/sync 回调内调用） */
void     SCL_Ret_Set(int v);                // 写 G_RETURN（供 if / while 判断）

/* 变量接口（供 C 命令使用） */
const char *SCL_VarGet(const char *name);   // 取变量值（不存在返回 NULL）
int         SCL_VarSet(const char *name, const char *val); // 0=成功
int         SCL_VarFreeCount(void);         // 剩余空槽数
int         SCL_VarCount(void);             // 已用槽数

/* 调试/帮助 */
void     SCL_Help(void);                    // 列出已注册命令
```

内置命令：`var`（建/列/全释放）、`free`（释放指定/全部）、`if`、`while`、`help`（可裁）。

### 5.6 移植接口

| 项 | 形式 | 说明 |
|----|------|------|
| 输出 | `void SCL_Port_PutChar(char c);`（用户实现） | 库内所有消息经它发出；`SCL_CFG_MSG_EN=0` 时整段裁掉，可完全不实现 |
| 可裁剪宏 | `SCL_CFG_*`（见 `scl_cfg.h`） | 槽数/长度/上限/缓冲/消息开关均可在编译期裁剪 |
| 依赖 | 无 malloc / 无 OS / 无 HAL / 无 libc 必需 | 若要错误码等整型转字符串，内部自带小格式化，不依赖 snprintf |
